## 1. 프로젝트 개요

**den** — 프로젝트 관리 + 메신저 사내 솔루션 (Dooray 영감). 전부 소문자 표기.

| 요소 | 이름 | 의미 |
|---|---|---|
| 조직 | pleanb | Lean하게 계획하고 Plan B를 제시하는 팀 |
| 제품(프론트) | den | 소수 정예가 방해받지 않고 일하는 디지털 아지트 |

- 목표: 사내 사용 → 검증 후 오픈소스 공개 + 유료 설치·지원으로 수익화

## 3. 완료 상태 — MVP 전체 완료

### 프론트 8단계 (2026-08-17 완료)
공통 토대 → 전체 프로젝트 홈 → 업무 리스트 → 업무 상세 →
권한·멤버 → 간트 뷰 → 메신저 → 알림

### 백엔드 8단계 (2026-08-29 완료)
공통 토대 → 엔티티 19개 → 인증(JWT) → 프로젝트·폴더·즐겨찾기 →
멤버·역할·권한 → 업무 → 댓글·알림 → 메신저(STOMP)

### 연동 4단계 (2026-08-30 완료)
axios+인증 → 프로젝트 → 업무·댓글 → 메신저·알림·권한 + 목업 전면 제거

### 추가 완료 (소급 불가라 선제 구현)
- **업무 활동 이력** `TASK_ACTIVITY` — status/priority/title/startDate/endDate/
  progress/assignees/isPrivate/dependencies 변경 기록
  (`GET /api/tasks/{id}/activities`, 상세 패널 "변경 이력" 섹션)
- **소프트 삭제** — TASK·PROJECT에 `deletedAt`. 프로젝트 삭제 시 하위 업무,
  업무 삭제 시 하위 업무 cascade. 모든 조회에서 `deletedAt IS NULL` 필터

**현재 상태**: 로그인부터 프로젝트·업무·간트·메신저·알림까지 전부 실제 백엔드로 동작.
목업 데이터 없음(`src/mock/types.ts`만 타입 계약용으로 남음).

## 4. 핵심 규칙 (어기면 안 되는 것)

1. **URL 우선 원칙** — 필터·뷰·그룹·페이지·검색어는 `route.query`에.
   `ref`에만 두면 뒤로가기가 깨진다. 상세 열기는 `push`, 닫기는 `replace`.
2. **검증은 프론트·백엔드 양쪽 모두.** "프론트에서 했으니 백엔드는 로직만"은 금물.
3. **권한 판단은 서버에서.** 멤버 아니면 404(존재 은닉), 메뉴 권한 없으면 403.
4. **URL에 프로젝트 UUID 노출 금지** — `projectKey`("APP") 사용.
5. **JPA**: `save()`로 INSERT/UPDATE 판단 위임 금지, `@DynamicUpdate` 금지,
   부분 수정은 "조회 → 필요한 필드만 세팅 → 전체 UPDATE".
6. **디자인 토큰만 사용** — 색·간격 하드코딩 금지. 인디고 액센트, 라이트 모드 전용.
7. **API-SPEC.md 계약을 임의로 바꾸지 말 것.** 바꿔야 하면 먼저 합의 후 문서 갱신.

## 7. AI 협업 방식 (실측으로 검증된 것)

**도구 분담**
- 설계·판단·트레이드오프 논의 → 채팅(claude.ai)
- 실제 코드 작성 → Claude Code (IDE 플러그인)
- 화면·API 확인 → **사람이 직접** (브라우저, curl)

**효율 규칙**
1. 단계 시작 전 `/clear` — 가장 효과 큼 (1,000줄당 비용 절반)
2. 수정 요청은 묶어서 한 번에 (5개 한 번 = 1회분 컨텍스트)
3. 수정 3회 넘으면 `/compact`
4. 브라우저 자동화 끄기 — 사람이 보는 게 정확하고 저렴
5. **외부 라이브러리 내부 동작 수정은 피할 것** — 1,000줄당 비용 3배

**실측 (프론트 8단계)**
3일 · 실작업 5시간 52분 · 순증 4,240줄 · API 환산 $38.92 · 주간 한도 25%
검토·판단 시간이 API 실행 시간의 **3배** (1h30m vs 4h20m)

**요금제**: Pro 유지. 세션 만료 대기 0회. 집중 작업이 몰리는 달만 Max 전환 검토.

**Claude Code 한계 (실측)**
- 대화형 CLI(create-vite, shadcn init) 실행 불가 → 사람이 직접
- 빌드 통과 ≠ 동작. 런타임 오류는 브라우저로만 발견됨
- 외부 라이브러리 블랙박스 수정에 약함
- 프레임워크 기본 세팅은 사람이 하고 코드만 시키는 게 안정적
